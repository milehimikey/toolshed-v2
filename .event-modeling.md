## Decisions log
<!-- Resolved choices, with the reasoning, so they aren't re-litigated. In a live workshop,
     attribute each entry to the participant who made the call (see Participants above). -->
- **2026-10-05 — Foundation events PR waits for the final event set** (Mike Key; ruled with
  deliver.lead, relayed to model.lead). Constitution Amendment 1 stands as written: the first
  delivery PR creates every event in the model, and it is held until slicing is finished and the
  `.em`'s event set is final, so nothing is built before then. model.lead pings deliver.lead when
  the last slice doc is written and no more events are expected — not at the close of the model
  phase. A later delta that adds an event to an already-merged slice still lands its event PR
  first (em contract §3). **Rejected:** (1) the emitting slice creates any event added during
  slicing in its own PR; (2) a separate events PR ahead of each slice that introduces events.
- **2026-10-05 — A hold is fulfilled when the tool is returned** (Mike Key). Hold Fulfilled is
  recorded at return: the tool is set aside for the neighbor at the front of the queue, and
  nobody else can check it out. That neighbor picks it up later. **Rejected:** fulfilled when the
  holder checks the tool out; two separate facts (set aside at return, then done at checkout).
- **2026-10-05 — A held tool's pickup is an ordinary checkout** (Mike Key). No separate pickup
  event; the holder's collection is Tool Checked Out. Who may check out a set-aside tool is a
  checkout-slice rule.
- **2026-10-05 — Overdue is derived, not recorded** (Mike Key). A loan past its due date is
  visibly overdue by comparing the due date with today; no "Loan Became Overdue" event. **Rejected
  as an event:** Loan Became Overdue (derived value — belongs in a read model). Expiry must
  trigger a notification to the borrower (an automation off an overdue-loans read model).
- **2026-10-05 — One overdue notice per loan, recorded** (Mike Key). The automation sends one
  notice per overdue loan and records Overdue Notice Sent; the record prevents a second notice
  and shows the borrower was told. **Rejected:** repeating notices on a schedule; sending without
  a record.
- **2026-10-05 — Loan period: tool default, set at checkout; borrower can extend** (Mike Key).
  Every tool defines its default checkout period; the due date is set when the tool is checked
  out. The borrower can extend/renew a loan during its life.
- **2026-10-05 — Extend and renew are one action: Loan Extended** (Mike Key). **Rejected:**
  extend and renew as two distinct events.
- **2026-10-05 — Tool Retired when a tool is removed from the shed** (Mike Key). The only
  tool-lifecycle event besides Tool Added named in step 1.
- **2026-10-05 — Neighbors can be suspended or close their account** (Mike Key). Neighbor
  Suspended for repeated late returns; Neighbor Account Closed when a neighbor moves away or
  stops participating (the neighbor's own choice).
- **2026-10-05 — Suspension: the system flags, a person decides** (Mike Key). Neighbors who
  reach a late-return threshold are flagged; a person who runs the shed makes the call to
  suspend. **Rejected:** automatic suspension at the threshold; a person deciding with no
  system flag.
- **2026-10-05 — Crossing the late-return threshold is recorded: Neighbor Flagged** (Mike Key).
  An automation records it when a neighbor reaches the threshold. **Rejected:** a derived list of
  neighbors at/over the threshold with no event.
- **2026-10-05 — The shed manager lifts suspensions: Neighbor Reinstated** (Mike Key). The
  person who runs the shed is the **shed manager**; they suspend and reinstate. **Rejected:**
  permanent suspension. (Offered but not chosen: suspension lifting automatically after a set
  time.)
- **2026-10-05 — Storyboard order** (Mike Key). Tool Added → Neighbor Registered → Tool Checked
  Out → Loan Extended → Hold Placed → Overdue Notice Sent → Tool Returned → Hold Fulfilled
  (holder then collects via an ordinary checkout) → Neighbor Flagged → Neighbor Suspended →
  Neighbor Reinstated → Tool Retired → Neighbor Account Closed. One story touches every event;
  Neighbor Flagged after a single late return is a storyboard compression of "repeated".
- **2026-10-05 — Who does what** (Mike Key). Personas: **Neighbor** and **Shed Manager**. The
  shed manager adds and retires tools (and suspends/reinstates). Neighbors sign themselves up,
  and check tools out and return them self-service. **Rejected:** neighbors adding tools; the
  shed manager enrolling neighbors; checkouts/returns recorded by the shed manager at a counter
  (or by either).
- **2026-10-05 — Hold Fulfilled is a system reaction to the return** (Mike Key). Returning a tool
  records only Tool Returned; an automation watches returned tools with holds waiting and
  fulfills the first hold in the queue. **Rejected:** the return action itself recording both
  Tool Returned and Hold Fulfilled.
- **2026-10-05 — Storyboard screens** (Mike Key). Shed Manager: Tool Inventory (add, retire),
  Flagged Neighbors (suspend), Suspended Neighbors (reinstate). Neighbor: Sign Up, Tool Catalog
  (check out, place hold), My Loans (extend, return), My Account (close account). System
  reactions: overdue notice, hold fulfilment, neighbor flagging.
- **2026-10-05 — Command names** (Mike Key). Add Tool, Register Neighbor, Check Out Tool, Extend
  Loan, Place Hold, Send Overdue Notice (system), Return Tool, Fulfill Hold (system), Flag
  Neighbor (system), Suspend Neighbor, Reinstate Neighbor, Retire Tool, Close Account.
- **2026-10-05 — Neighbors see holds on a My Holds screen** (Mike Key). New neighbor screen: their
  holds, queue position, and "ready for pickup" once fulfilled. **Rejected:** holds shown on My
  Loans; holds visible only through the Tool Catalog.
- **2026-10-05 — Shed Manager has a Neighbors screen** (Mike Key). Lists all neighbors with status
  (active, suspended, closed); account closures surface there. **Rejected:** closure visible only
  on the neighbor's own My Account.
- **2026-10-05 — Read models** (Mike Key). Tool Inventory (Tool Added, Tool Retired); Tool Catalog
  (Tool Added, Tool Checked Out, Tool Returned, Hold Placed, Hold Fulfilled, Tool Retired); My
  Loans (Tool Checked Out, Loan Extended, Overdue Notice Sent, Tool Returned); My Holds (Hold
  Placed, Hold Fulfilled, Tool Checked Out by the holder); Overdue Loans To Notify (Tool Checked
  Out, Loan Extended, Tool Returned, Overdue Notice Sent); Holds To Fulfill (Hold Placed, Tool
  Returned, Hold Fulfilled); Neighbors To Flag (late Tool Returned, Neighbor Flagged); Flagged
  Neighbors (Neighbor Flagged, Neighbor Suspended); Suspended Neighbors (Neighbor Suspended,
  Neighbor Reinstated); Neighbors (Neighbor Registered, Suspended, Reinstated, Account Closed);
  My Account (Neighbor Registered, Neighbor Account Closed). The three "To …" views are the
  automations' to-do lists.
- **2026-10-05 — Automation to-do lists: one instance before the processor; completions loop
  back** (raised by Mike Key on the diagram; layout by model.lead). A processor reads only the
  nearest view instance at or before its slice, so each to-do list has a single instance right
  before its processor, fed by every earlier event (longer arrows accepted). Events that clear an
  item after the processor (Overdue Notice Sent, Tool Returned → Overdue Loans To Notify; Hold
  Fulfilled → Holds To Fulfill; Neighbor Flagged → Neighbors To Flag) use `loops-to`.
  **Rejected:** span-1 to-do instances with no consumer; dropping the completion feeds.
- **2026-10-05 — Four swimlanes** (Mike Key). Tools (Tool Added, Tool Retired); Loans (Tool
  Checked Out, Loan Extended, Overdue Notice Sent, Tool Returned); Holds (Hold Placed, Hold
  Fulfilled); Neighbors (Neighbor Registered, Flagged, Suspended, Reinstated, Account Closed).
  Lanes organize the picture; a command's rules may still read across lanes. **Rejected:** three
  lanes (holds folded into a Lending lane); two lanes (tool vs neighbor).
- **2026-10-05 — Overdue notices go out through an email/SMS provider** (Mike Key). Delivery
  crosses a boundary, so Send Overdue Notice is triggered by a **translation** (the provider
  adapter) watching Overdue Loans To Notify, not a processor; Overdue Notice Sent records the
  hand-off. Which channel(s), and what a delivery failure means, are slicing questions.
  **Rejected:** in-app only; deferring the delivery route to slicing.
- **2026-10-05 — Decision brief 1 answered** (Mike Key: "accept all recommendations, email only,
  no edit or verification"; T3/T7 asked separately).
  - T1 A tool has a name (required) and a description (optional); Tool Inventory and Tool
    Catalog show these and the default checkout period.
  - T2 Each physical item is its own tool. **Rejected:** one tool with a quantity.
  - T3 Default checkout period is whole days, at least 1, with a maximum cap (value not yet
    named). **Rejected:** no maximum.
  - T4 A tool can be borrowed as soon as it is added. **Rejected:** a step between add and lend.
  - T5 A tool's details and default period can't be edited; a mistake is fixed by retiring and
    re-adding. **Rejected:** a Tool Details Changed event.
  - T6 A retired tool drops off Tool Inventory and Tool Catalog. **Rejected:** listed as retired.
  - T7 A checkout may choose a period **shorter** than the tool's default, never longer.
    **Rejected:** always the default; any period up to a cap.
  - C1 A returned tool with holds waiting is not shown available before Hold Fulfilled.
  - C2 Holds only on a tool that is checked out or set aside. **Rejected:** holds on available tools.
  - C3 Tool Catalog shows how many holds are waiting.
  - C4 "Set aside for you" shows only on My Holds; the catalog is the same for every neighbor.
  - C5 Tool Catalog shows a checked-out tool's due date — **model change:** Loan Extended also
    feeds Tool Catalog.
  - N1 Overdue notices go by **email only**; sign-up collects name and email. **Rejected:** SMS;
    both.
  - N2 One account per email; a second sign-up with the same email is refused.
  - N3 No approval and no contact verification before borrowing. **Rejected:** a verification
    event/slice; shed-manager approval.
  - N4 A closed account's owner may sign up again as a new account (the Neighbors screen shows
    both entries). **Rejected:** reopening the old account.
  - N5 A suspended neighbor may close their account; closed is final and is what shows.
  - N6 My Account shows suspension and reinstatement — **model change:** Neighbor Suspended and
    Neighbor Reinstated also feed My Account.
  - N7 After closing, the neighbor can still view My Account, read-only.
- **2026-10-05 — Decision brief 2 answered** (Mike Key: "accept all recommendations, pickup
  window 3 days").
  - N8 Two tools may share a name. **Rejected:** unique tool names.
  - N9 A sign-up may reuse a closed account's email, unless that account was suspended when it
    was closed. **Rejected:** never reuse; reuse freely.
  - N10 After signing up again, My Account shows only the new account.
  - K1 Suspended and closed neighbors can't check out (suspension's effect).
  - K2 Between a return and Hold Fulfilled, only the front holder may check the tool out.
  - K3 An overdue loan also blocks a holder from collecting a set-aside tool.
  - K4 No limit on concurrent loans per neighbor.
  - K5 A shorter loan period is chosen in whole days, at least 1. **Rejected:** a return date.
  - L1 An extension adds one default checkout period to the current due date. Refused while any
    hold is waiting on the tool, and refused once the loan is overdue. No cap on the number of
    extensions otherwise.
  - L2 A returned loan drops off My Loans. **Rejected:** loan history with a late marker.
  - L3 My Loans shows the checkout date. · L4 No "due soon" state.
  - H1 A neighbor can cancel a hold — **new event Hold Cancelled** + slice (from My Holds).
  - H2 A set-aside tool has a **3-day pickup window**; when it lapses the hold expires and the
    tool passes to the next hold, or becomes available — **new event Hold Expired** + automation.
    **Rejected:** set-asides that never end; shed manager cancelling by hand.
  - H3 Retiring a tool ends its holds (no new event; hold views hear Tool Retired).
  - H4 Closing an account ends the neighbor's holds (no new event; hold views hear Neighbor
    Account Closed). A suspended neighbor keeps their place but can't collect while suspended.
